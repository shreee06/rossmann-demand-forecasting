# Data audit — Rossmann Store Sales

_Generated by `scripts/audit_data.py`; all numbers come from `evals/results/data_audit.json`. Source: Rossmann store data from the Kaggle competition `rossmann-store-sales`; raw data is not included in this repository._

**Scopes.** Structure and data-quality counts (sections 1-4, 8 and the holiday coverage counts in 7) use all 1,017,209 rows. Sales-based descriptives (sections 5, 6, 9, 10 and the sales contrasts in 7) use only rows before the TEST window (dates up to 2015-06-19), so nothing about test-window sales informs modelling choices.

## 0. Known at forecast time vs not

| Column | Known in advance? | Note |
|---|---|---|
| Store, StoreType, Assortment, CompetitionDistance, CompetitionOpenSince*, Promo2, Promo2Since*, PromoInterval | Yes | Store attributes (slowly changing; treated as static) |
| Date, DayOfWeek | Yes | Calendar |
| StateHoliday, SchoolHoliday | Yes | Published holiday calendars |
| Promo | Yes (assumed) | Planned promotions are scheduled ahead; assumed available for the forecast horizon |
| Open | Partly | Regular opening pattern is known; unplanned closures are not. Handling is decided at modelling time |
| Sales | No | Target |
| **Customers** | **No** | **Observed only together with Sales. Never a feature and never used to build features (enforced by tests).** |
